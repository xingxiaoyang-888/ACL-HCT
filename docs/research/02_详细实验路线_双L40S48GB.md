**详细实验路线：采样诱导层级坍缩与切空间轻量修正**

版本：V1.0｜日期：2026-09-14｜目标硬件：2 × NVIDIA L40S，每卡 48GB。

这是迁移到新电脑后使用的执行设计，不表示实验已经开始。本文的网格、阈值、脚本名和时间场景均为拟定方案；正式运行前按数据审计、实现验证及性能测量锁定版本。已有局部推导只提供候选方法，不替代“层级坍缩”的真实证据，也不把研究目标收缩为一种聚合的均值估计。

**00．阅读顺序与执行边界**

先读 01–08，理解问题、硬件、数据、模型、指标和公平比较；随后按 E0–E9 执行；最后用运行矩阵、统计规范和交付清单完成论文实验。核心路线始终为：采样造成的层级结构损伤 → 几何解释 → 切空间修正 → 真实任务和成本验证。

执行优先级：P0 是环境、数据、理论和机制检查；P1 是核心方法验证；P2 是兼容性、规模、消融及边界。P2 用于完成相应论文主张，不能在主张保留时省略必要证据。本文不要求把所有维度做完整笛卡尔积。

**01．把研究主张落实到证据**

| 主张 | 必需证据 | 支撑不足的情形 |
|---|---|---|
| C1：采样可诱发层级坍缩 | 固定模型时，层级顺序/分支可分性随采样受损；有条件分组、重复性和实际效应量 | 只有输出半径变化或单次采样波动 |
| C2：存在可解释的几何机制 | 偏移方向/幅度与理论变量一致；与匹配的零均值噪声、数值误差、普通传播退化区分 | 只有相关性或只在一个极端构造中存在 |
| C3：小模块可缓解坍缩 | 层级指标和任务收益与机制干预一致，并报告不改善的场景 | 只减小几何偏差，MSE或任务持续恶化 |
| C4：方法轻量且可复用 | 同时间预算、峰值显存、不同骨干和采样预算上的比较 | 仅报告参数数目或单一网络结果 |

“坍缩”的工作定义：采样及其传播使原本可分的层级或分支信息被系统性削弱。事先锁定判定协议：至少有一种直接结构指标出现可重复且具有实际幅度的恶化，并有另一种独立结构指标或任务指标相互支持。统计显著性不能代替实际幅度；不预先强行设定所有任务必须下降同一个百分比。

开发阶段用验证集界定每个任务的最小有意义差异，记录依据；测试集打开前冻结。若最终仅支持局部失真，应按证据报告，不能把轻微扰动改名为严重坍缩。

**02．全局默认配置及其身份**

下表是迁移后的启动配置，不是已经调优的最佳值。

| 项目 | 默认启动值 | 如何调整 |
|---|---|---|
| 主骨干 | Lorentz-Mean、Lorentz-Attention | 各自有明确代码来源或标为自建受控模型 |
| 隐空间维数 | 128 个空间维度；Lorentz总坐标129 | 消融64、256；比较时说明参数匹配或维度匹配 |
| 层数 | 2 | 真实大图补3层；4/8层优先在可完整逐层处理的图上分析 |
| 曲率 | 每层固定 c=1，即截面曲率−1 | 敏感性 c∈{0.01,0.1,1,4}；另设真正欧氏对照 |
| 训练采样 | 每跳fanout为8或16，无放回 | 每节点实际k=min(fanout,N)，记录实际覆盖率 |
| 推理采样 | 4、8、16、32、64、全部可见邻居 | 去掉重复的实际配置；低度节点单独统计 |
| 目标节点batch | 两层模型1024 | 高fanout从256起；以采样消息/节点数上限保护显存 |
| 优化器启动方案 | 欧氏参数AdamW；流形参数用明确的流形更新或重参数化 | 参数类型与优化器需逐项列出，不默认对流形坐标直接AdamW |
| 学习率搜索 | 1e−4、3e−4、1e−3、3e−3 | 相同搜索预算；记录所有失败配置 |
| 权重衰减 | 0、1e−5、1e−4 | 不能对不适合欧氏衰减的流形坐标混用 |
| Dropout | 0、0.1、0.3 | 几何机制测量一律关闭；训练各方法一致 |
| 正式训练种子 | 11、23、37、53、71 | 探索先用11、23、37；测试结果不用于决定是否补种子 |
| 自建数据划分种子 | 20260914 | 划分一次后保存清单及SHA256；OGB沿用官方划分 |
| 精度 | 主训练几何部分FP32；小规模机制FP64 | BF16只在后续通过检查的欧氏计算中启用 |

fanout是每跳最大采样数量，不是全图采样比例。理论中的N是当前聚合操作在可见图上的完整候选消息数；不能用全图节点总数代替。层级、关系和方向都可能改变N的定义。

**03．双 L40S 的硬件、内存和精度安排**

官方规格为每卡48GB GDDR6 ECC、PCIe Gen4接口、无NVLink。默认两张卡各运行一个独立训练任务，提高不同方法和种子的吞吐；两卡不是自动共享的96GB显存。[NVIDIA L40S规格](https://www.nvidia.com/en-gb/data-center/l40s/)

只有单任务实测能明显受益时才使用DDP。DDP同步模型副本的梯度，输入分配由程序处理；它不会自动把单个模型和图的内存分摊到两卡。[PyTorch DDP文档](https://docs.pytorch.org/docs/main/generated/torch.nn.parallel.DistributedDataParallel.html)

迁移后先登记：GPU型号/UUID、驱动、CUDA运行时、PyTorch/PyG及采样后端版本、CPU型号和核心数、RAM、磁盘类型与剩余空间、PCIe拓扑、操作系统。默认目标环境为Linux；具体依赖组合按目标机驱动和可用轮子确认后锁定，不在本文虚构已安装版本。

建议准备128GB主内存，图缓存和双任务较多时256GB更宽裕；为所选数据、特征和checkpoint预留约200–500GB NVMe工作空间。这是容量规划，不是实测需求；实际下载大小和缓存上限在数据审计后更新。

显存规划：每卡先把训练峰值控制在约38–40GB以内，为不同batch的邻域波动留余量。OOM依次处理：降低目标节点batch、限制单batch消息数、启用双方相同的缓存/分块策略；改变fanout会改变研究条件，必须作为新配置，不能当作无影响的工程修复。

对于B个目标节点、L层、每跳fanout k_l，不考虑邻域重叠时，节点数上界为：

$$n_{batch}\le B\left(1+\sum_{l=1}^{L}\prod_{j=1}^{l}k_j\right).$$

B=1024、两层16邻居时，上界279,552个节点。一份128维FP32空间特征约143MB；实际训练还有时间坐标、边消息、多头、中间激活、梯度和缓存，不能据此说整次训练只需143MB。深层不能直接把16邻居重复到8层，必须采用可控的逐层图处理来做深度机制分析。

精度策略：

- 几何正确性、微小偏差和符号检查用CPU FP64或小规模GPU FP64；不把L40S当作高吞吐FP64专用卡。
- Lorentz内积、归一化、Log/Exp、acosh、切向矩累积默认至少FP32，必要时局部FP64重算。
- 初始阶段关闭会改变精度路径的TF32/混合精度优化，后续分别报告提速结果。
- clamp、距离下界、半径裁剪必须记录触发率；若结论由大量clamp驱动，先处理数值问题。
- 欧氏层BF16是可选工程优化，所有比较方法一致，并用FP32/FP64子集核对。

| ID | 数据与版本规划 | 证据职责 | 关键边界 |
|---|---|---|---|
| D0 | 自建受控树、层级DAG及非层级对照 | 真值明确的机制与传播分析 | 不称为真实网络证据 |
| D1 | WordNet 3.0名词synset及hypernym关系 | 深度顺序、祖先关系恢复 | 多父关系、低度节点、已知结构泄漏 |

**05.1．所有真实图都先执行的数据审计**

保存节点数、边数、方向、重复边、自环、连通分量、每关系度分布、标签缺失率、多标签率、深度分布、不同划分交叉情况。去重和删除规则必须一致、确定、可重建。

对每个fanout f报告：P(N_i>f)、实际k_i/N_i分布、被抽掉的消息总比例；同时分层报告高/低度、深/浅层、不同类别和每个网络层。至少报告全体节点及真正发生删减的节点两个口径，不能只展示受影响子集。

若taxonomy中大多数节点N≤f，保留它作为低删减边界；重点检查自然高连接节点和D3/D5。可以在D0中增加受控跨层边；若对真实图构造多跳候选邻域，应明确作为派生设置，独立报告，不能混称原始图结果。

**05.2．D0：合成数据需要控制哪些因素**

生成平衡树、不平衡树、多父DAG和加入兄弟/跨层连接的图。树/DAG的真实层级T与用于消息传播的图G分别保存；G可以含非层级关系，T不变。增加连接时单独控制度数与层级深度的相关性，避免所有深节点都恰好低度。

初始规格：规模1千、1万、10万节点；深度4、8、12；每个条件5个生成种子。先固定一组规模和深度分别扫描其他变量，再选择有明确意义的交互，不做全交叉。

输入特征分为：带可控层级信号、随机无结构信号、弱特征三类。精确层级坐标只用于算子诊断，不混作未知结构预测。训练/评估节点或子树划分固定；任务包括祖先排序、分支识别和有噪声的层级标签预测。

**05.3．D1、D2：区分结构保真与未知关系恢复**

建立两个独立协议，不能混用完整图与删边图的结论。

- 协议A：已知taxonomy的表示保真。T可用作消息图，测量完整/采样传播保存了多少已知结构。它是表示分析，不宣称预测了未知边。
- 协议B：部分可见结构下的关系恢复。先按子节点ID把父边分成80%训练、10%验证、10%测试；同一子节点的全部待监督父边归同一划分。消息图只含训练可见边及其显式反向边。验证/测试父边、反向边、由它们生成的闭包边都不得进入消息图。

协议B允许删边后形成森林和孤立节点，报告比例，不能为了连通性偷偷补回测试父边。所有方法使用同一观测图G_obs。负样本从预先固定且带标签的候选关系集合建立，训练仅使用训练标签；测试排名可采用过滤已知其他真父节点的协议，但过滤器不得提供给训练过程。固定候选集合与过滤规则，并同时报告候选规模；抽样候选排名与全候选排名不能混为一个指标。

D1按synset保留多父关系；名词与实例hypernym是否都包含先锁定。单一深度分析使用最长根路径深度和最短深度的敏感性对照，不能随意把DAG变成一棵树。若由全真值T计算深度，只允许评估器读取；模型/修正器不读取测试深度。

D2优先按descriptor作为唯一实体，保留所有tree路径；“前缀对应父位置”用于生成结构，不能把tree number当作输入特征。若做位置展开，所有属于同一descriptor的副本必须同一划分。多位置实体使用路径/祖先集合指标，不强制一个半径表示所有路径深度。径向深度分析可单列单路径实体，并报告覆盖率；完整数据仍需评估。MeSH官方说明明确允许一个descriptor出现在多个位置。[MeSH Tree Structures](https://www.nlm.nih.gov/mesh/intro_trees.html)

可见结构参考始终是G_obs的完整邻域，不是把测试边补回后的图。这样“完整邻域”不会变成测试信息上界。

**05.4．D3：真实商品关系图与层级任务**

先只取Electronics领域元数据，使用产品ID及also-buy/also-view关系；字段名以下载文件的实际schema为准，不能假定官方示例与每个文件完全相同。类别路径、显式分类字段和由标签构造的边不进入输入关系图。元数据来源确实提供关系与类别信息，具体可用覆盖率尚未验证。[Amazon 2018说明](https://cseweb.ucsd.edu/~jmcauley/datasets/amazon_v2/)

步骤：

1. 流式解析JSON，按产品ID合并重复记录；生成缺失、冲突和去重清单。
2. 核查category/categories是有语义顺序的路径、多个路径，还是无序标签。无序标签不能人为按数组下标赋予层级。
3. 经核查的路径按完整前缀形成类别ID，避免不同分支中的同名类别被错误合并。多路径保留为标签集合。
4. 关系只保留已纳入节点集合的端点；报告截断损失。主设置合并为无向去重图，方向/关系类型作为补充设置。
5. 产品按ID稳定分为70/10/20训练/验证/测试；识别到的同一商品变体/重复文本组保持同一划分。类别只在测试出现时标记为开放类别，不悄悄丢弃。
6. 主任务为由产品关系及文本预测多层类别。候选标签体系取训练可见标签；同时报告闭集覆盖率和未见类别比例。使用共享的各层分类头或统一多标签头，原模型与修正模型完全一致。
7. 层级指标为每层macro-F1、祖先集合F1、固定深度上的同分支检索；产品不是祖先节点，不能对产品硬套“父产品在内、子产品在外”。

若路径语义不能可靠建立，D3保留为平面任务但不支撑层级坍缩；使用经核查的Home and Kitchen领域作为预先列出的替代候选，记录更换原因。更换依据仅限数据可用性与标签语义，不按方法是否取得正结果挑选数据。

**05.5．输入特征与任务头**

D4/D5优先官方特征。D1/D2/D3启动方案为名称/定义/标题/描述的TF-IDF，再用仅在训练实体文本上拟合的SVD投到128维，词表、IDF和SVD全部冻结。删除直接的category路径和tree编码字段；自然文本中的类别词不伪装成完全无语义信息，另以无图MLP衡量文本贡献。

如果该启动文本特征不足以构成有竞争力的任务基线，再统一替换为固定的公开文本编码器，登记模型版本、tokenizer、最大长度、编码成本和预训练来源，所有图方法共享缓存；不把文本模型的改变归因于几何模块。

任务头只用训练标签学习；验证集选配置；测试标签仅供最终评估。DAG/多标签任务明确损失、正负采样比、阈值选择与候选排名方式。不得只给修正模型增加层级监督或更强解码器。

**05.6．可直接启动的任务损失与查询规则**

D1/D2协议B：对有序候选(a,d)，用两层MLP对[Log_o(z_a),Log_o(z_d),Log_o(z_a)−Log_o(z_d)]打分；欧氏骨干将Log_o换为恒等映射。隐藏层启动为128维，二分类BCEWithLogits损失，每个正关系配4个负关系，先用固定均匀候选负例，再单列结构匹配难负例。MLP是启动头，另以统一的几何方向性头作敏感性检查；头部选择对所有修正方法一致。

训练的每个查询正边及其反向边从该batch的消息图临时屏蔽，避免直接读取目标边；同batch多个目标边统一屏蔽，N按屏蔽后的候选集计算。验证/测试目标边原本就不在G_obs中。监督查询和消息图输入分开保存，检查采样器不会把目标边重新加回。

taxonomy主排名尽量对全部合法父节点候选计算，分块打分避免显存峰值；若使用固定抽样候选作为开发加速，固定每查询1000个候选并单独命名，最终不与全候选MRR混报。难负例的生成仅使用该阶段允许的标签/结构；完整真值过滤限于评估器。

D3采用多层类别的多标签BCE，启动为一个共享两层MLP输出所有训练可见类别；各层结果由标签映射拆分。类别权重只用训练频次计算，是否采用及上限在验证集冻结；阈值同样只在验证集选。标签类别体系公开程度、未知类别口径和输入字段分离需要同时记录。

D4/D5采用官方标签的多类交叉熵和共享分类头。无图MLP使用相同特征；taxonomy的无图对照保留同一有序关系头，只去掉图传播。关系任务的batch_size指目标查询数，节点分类的batch_size指目标节点数，二者不能直接当作相同消息规模。

**06．骨干、模块与基线接口**

**06.1．三类骨干的角色**

| 模型 | 聚合机制 | 实验角色 |
|---|---|---|
| L-Mean | 正权等权Lorentz向量求和后归一化 | 可解释主骨干；可采用LGCN式组件但自建时明确标记 |
| L-Attn | 双曲/切空间得分生成正权重，再做Lorentz质心 | 主要兼容性骨干，先固定权重再允许正常重算 |
| HGCN类切空间聚合 | 在明确基点Log、聚合、Exp | 跨聚合家族验证，需要独立适配，不能直接套L-Mean定理 |

基础方法来源：[Lorentzian Graph Convolutional Networks](https://arxiv.org/abs/2104.07477)、[Hyperbolic Graph Convolutional Neural Networks](https://arxiv.org/abs/1910.12933)。旧骨干用于机制可解释性；近期组件需作为对应强对照，避免仅击败过时实现。

模块插在聚合之后、残差/归一化之前作为首版位置；记录每一层、每个头/关系的曲率和候选消息。不同曲率的消息先按骨干既有规则进入共同空间，再修正；跨曲率合并不能直接相加。

**06.2．当前候选公式，只锁定为一个研究分支**

模块输入：本次样本消息、当前输出p_hat、完整候选数N、实际样本数k、曲率c、权重和采样协议。输出：修正后的点及诊断元数据。任何未采样隐藏消息、全邻域正确输出、真实层级标签只可进入oracle诊断，不能进入可部署方法。

对等权Lorentz质心、均匀无放回采样、局部邻域、3≤k≤N，已有候选：

$$A=\frac{N^2(k-1)(k-2)}{k^2(N-1)(N-2)},\quad w_j=\operatorname{Log}_{\hat p}(x_j),\quad v_j=w_j-\bar w,$$

$$\widehat M_3=\frac1k\sum_j\|v_j\|^2v_j,\quad \alpha=\frac{c(1-A)}{6A},\quad p_{corr}=\operatorname{Exp}_{\hat p}(\alpha\widehat M_3).$$

这是局部主导偏差修正，尚非全局最优模块。纯解析版先保留，无额外损失；主训练允许沿公式正常反传。stop-gradient、阻尼和步长上限分别作为可解释变体，不悄悄加入后仍声称纯解析保证。

N=0用原骨干的无邻居输出；k=N原样返回；N≤2或k≤2时该公式不适用，首版回退原输出并记录比例。未来低k方案需要额外推导，不能设一个极小分母强行执行。回退覆盖率直接关系到方法的实用价值。

大分散邻域中可测试可靠性阻尼：step←λ step，λ由验证集锁定或由明确的局部指标推导；也可限制切向步长相对于局部分散程度的大小。记录触发率，重新说明保证边界。

**06.3．注意力与采样语义必须逐式核对**

固定非等权时，等权三阶矩系数A不直接适用。先对带权消息推导环境均值与协方差，再分析归一化；不要随意把k替换为“有效样本量”就宣称公式成立。

若骨干严格为F(Σ softmax(s_j)x_j)，且F是正比例不变的Lorentz归一化，则softmax的共同分母会在F中抵消。此时不能笼统声称“子图softmax分母变化必然增加一个独立比值偏差”。但得分依赖前层随机表示、存在dropout或其他组合操作时仍有额外因素，要按实际代码分析。数值上统一平移logit不应改变输出。

在异构图中先按关系分别定义N、k及曲率；若原始sampler返回诱导子图或双向补边，实际消息不一定是独立的均匀k子集。机制实验使用可检查的逐目标节点采样；部署兼容性再测标准loader的真实行为。[PyG采样接口说明](https://pytorch-geometric.readthedocs.io/en/latest/tutorial/neighbor_loader.html)

自环首版放在独立的残差路径，不计入均匀抽样的N、k。若骨干要求自环必选，应按“确定性消息＋随机邻居”的估计量重新推导；不能把必选自环伪装成普通无放回样本。

**06.4．基线清单与公平性**

| ID | 基线/变体 | 必须排除的替代解释 |
|---|---|---|
| B0 | 原骨干原聚合、相同采样预算 | 改善是否来自模块 |
| B1 | 完整可见邻域推理；小图补完整邻域训练 | 采样的作用以及完整参照自身的表现 |
| B2 | 仅由N/k/c控制的径向缩放，验证集选幅度 | 是否只是普遍改变表示尺度 |
| B3 | 几何jackknife偏差校正 | 通用统计消偏是否已经足够 |
| B4 | 更大fanout或多次采样聚合，匹配实际时间预算 | 是否不如把成本用于多采邻居 |
| B5 | GraphSAGE/欧氏注意力，任务头与特征相同 | 是否需要双曲机制 |
| B6 | 无图MLP | 是否只靠节点文本/特征即可解决任务 |
| B7 | OEM式半径加权的图聚合适配 | 是否已有简单径向pooling即可解释收益 |
| B8 | 原骨干＋近期Lorentz基础层/归一化组件 | 是否修复的只是基础层参数化或数值缺陷 |

B7是针对性图适配，不能称为HypRAG原系统复现；B8可以选ILNN组件，必须保持采样和任务头一致。[HypRAG](https://arxiv.org/html/2602.07739v2)、[ILNN](https://arxiv.org/html/2602.23981v1)

几何jackknife缓存样本总和后，全部leave-one-out质心同样可在O(kd)计算；不能宣称我们比它低一个复杂度阶。对无限总体的一阶jackknife，常用形式在当前中心Y处估计(k−1)mean Log_Y(Y_{−j})，并沿其负方向修正；有限总体需要明确的有限总体因子/推导。将有限总体修正作为预先记录的基线版本，不能挑一个明知目标不匹配的弱实现。

**06.5．简单缩放与jackknife的启动版本**

B2先采用z'=Exp_o(g Log_o(z))，g=exp[β(1−k/N)]，β∈{−1,−0.5,0,0.5,1}只用验证集选；它在k=N时不改输出。补一个使用相同N/k/c输入、极小参数量的自适应缩放，检验解析模块是否优于一般校准。若核心表仅采用前一种，后者属于预先记录的补充，不混用名称。

B3启动为有限总体一阶jackknife候选：

$$p_{JK}=\operatorname{Exp}_{Y}\left[-\lambda(1-k/N)(k-1)\frac1k\sum_j\operatorname{Log}_Y(Y_{-j})\right],$$

λ∈{0.25,0.5,1}在验证集选择。因子(1−k/N)是按领先有限样本项设置的版本，须在E1验证；不宣称有限k下严格无偏。另保留不加该因子的普通版本作敏感性对照。固定非等权时leave-one-out必须保留正确剩余权重；k=1回退，k=N原样返回。这个明确接口既避免弱基线，也给后续更精确推导留下空间。

**07．指标：几何、结构、任务、成本各自测什么**

**07.1．固定完整输出下的几何指标**

固定节点i和层l的完整输出p，对R次采样令ξ_r=Log_p(p_hat_r)。保存：

$$\bar\xi=R^{-1}\sum_r\xi_r,\quad B=\|\bar\xi\|,\quad MSE=R^{-1}\sum_r\|\xi_r\|^2,$$

$$V=R^{-1}\sum_r\|\xi_r-\bar\xi\|^2.$$

在这个固定切空间和上述分母下，经验MSE=B²+V；不把它推广成任意流形上所有中心定义的分解。径向分量用语义参考o在p处的向外单位向量e_r，计算〈barξ,e_r〉；横向分量单独记录。p=o时径向方向未定义，单列。

有限R下，B即使在真实零均值时也倾向大于零。推断时使用方向投影的置信区间；或用两组独立重复的均值内积估计||Eξ||²。后者估计可为负，不能在显著性分析前截断为零。展示B时提供抽样误差，不把小的正值自动称为系统偏移。

同时报告理论预测与实测偏移的方向余弦、投影回归斜率、残差，以及曲率/采样率/不对称性分组。不同节点的向量不在同一切空间，不直接求全图向量平均；用各自径向标量或明确的平行移动规则比较。

**07.2．直接层级指标**

1. 祖先顺序准确率：对真祖先a与后代d，检验语义根参考下r_a<r_d；报告深度差、分支和多父子集，排除无法定义单一深度的情况。径向规则本身不适用于所有骨干，先验证完整参照确实编码该信息。
2. 祖先/父节点检索：使用固定方向性评分头排名，报告MRR、Hits@10、候选数及filtered/unfiltered口径。不能仅用对称距离声称恢复了方向。
3. 分支三元组准确率：同深度或匹配深度的a,b来自同分支，c来自其他分支，检验d(a,b)<d(a,c)。三元组清单固定，避免只选简单负例。
4. 深度与半径的Spearman相关：作补充，不能单独支持坍缩；对DAG按既定多深度规则计算。
5. 层级分类：D3报告每层macro-F1、叶类别指标、祖先集合F1和跨分支检索。多路径真值按集合评价；若使用祖先闭包预测，原始预测和闭包后指标均报告。

诊断图可展示各深度的分布重叠、分支距离间隔及有效秩，但不把任一图形当作唯一主指标。全体共同的径向放大可能改变间隔而不改变顺序，应同时检查对尺度不敏感的排序指标。

**07.3．任务与效率指标**

taxonomy协议B以关系恢复的MRR/Hits@10为主；D3以预先锁定的层级macro-F1为主；D4/D5用官方准确率/evaluator。辅以校准或不确定性指标时说明意义，不临时挑有利指标当主结果。

效率包括：每步训练耗时、完整epoch耗时、固定查询数的推理耗时、p50/p95 batch延迟、节点/边吞吐、峰值allocated/reserved显存、CPU RAM峰值、实际消息数、clamp/回退率。端到端时间包括采样与CPU→GPU搬运；纯kernel时间单独列。

**08．公平比较和预先冻结的协议**

- 相同图、特征、划分、头部、负样本规则、训练目标和验证策略；模型容量差异列出。
- 配对方法使用相同初始化、目标节点顺序、负样本和采样计划。采样计划用独立随机数流或哈希规则，不依赖模型前向调用次数。
- 冻结网络诊断关闭dropout，BatchNorm使用相同冻结统计；记录残差和归一化前后位置。
- 完整/采样输出比较分两种：固定同层输入的局部采样，以及各层都正常采样的端到端传播。两者使用不同字段，不能相减后统称单层偏差。
- 存在可学习曲率时，只在同一checkpoint对应曲率上计算内蕴误差。跨checkpoint比较使用任务指标或明确的无量纲尺度；不能直接在不同流形坐标中相减。
- 原模型与修正模型分别在相同预算内调参，同时补同超参数的配对比较。不能只调新模型。
- 测试结果只在配置冻结后产生；对探索中使用过的数据明确标记，预留最终确认划分。

**09．E0：实现正确性和采样语义验收〔P0〕**

目的：先确认后续观察来自模型机制，不来自坐标、采样或评估错误。以下是在新机器实现后执行的必要检查，本文未执行。

步骤：

1. 验证Lorentz点满足〈x,x〉_L=−1/c，切向量满足〈x,v〉_L=0，Log/Exp互逆和测地距离公式一致。使用相对误差和不同半径分组，不用单一绝对容差覆盖所有尺度。
2. 对自动微分与FP64有限差分做小规模核查；只检查核心几何和修正项，不为配置文件编写镜像测试。
3. 对归一化质心检查邻居排列不变性、正权重共同缩放不变性、同点聚合、完整采样不变以及k=1/2回退。
4. 比较CPU FP64、GPU FP64和GPU FP32；报告可接受数值区间、约束残差、clamp频率。容差在精度检查后记录。
5. 用小图直接枚举可选邻居集合，检查每个节点抽样概率、无重复性、方向与N/k；确保loader没有加入未计入的诱导边。
6. 构造“高fanout≥所有N”的配置，要求采样版与分块完整推理一致。若不一致，先检查多层执行、BatchNorm、dropout与边补全。
7. 固定输入，验证注意力共同分母抵消是否适用于实际聚合；比对原公式和等价实现。
8. 检查修正器不读取oracle字段；让代码在传入测试深度、完整隐藏邻域时显式报错或禁止该接口。

输出：geometry_check.json、sampler_check.json、precision_ranges.md、源码commit。通过条件是基础恒等关系与采样概率可解释，非“新模块必须提升指标”。

**10．E1：受控机制和候选公式验证〔P0〕**

目的：区分偏差、方差、半径非线性效应，并验证候选公式适用范围。

第一部分为固定邻域，不训练网络。条件包括：对称分布、不对称长尾、方向旋转、同N/k但相反不对称性、同均值不同方差、相似方差不同三阶矩、同局部形状但整体作双曲等距变换。单测地线例子和真正多维分布分开。

基础网格：N∈{4,8,16,64,256}，k∈{1,2,3,4,8,16,32,N}且去掉k>N；维数∈{2,16,128}；c∈{0.01,0.1,1,4}。先固定N=16、d=2、c=1扫描不对称性和k，再选几个机制交互验证，避免全网格耗费。

第二部分为D0的图级传播。使用已知层级坐标作为一个诊断输入，同时补弱特征训练出的表示，观察现象是否只依赖人工坐标。让度数、深度、长尾比例和跨分支连接分别可控。

比较原聚合、候选修正、B2缩放、B3 jackknife、零均值匹配噪声。小N枚举所有子集；大N用固定重复计划。扫描局部半径ε时检查误差随ε的阶数，同时保留大分散区间，不截掉公式失效的部分。

输出：偏移与k/c/不对称性的曲线、方向预测图、MSE和方差、低k回退、大分散失效图。候选公式的局部正确性与它是否降低总误差分别判断。

**11．E2：冻结真实模型的采样诊断〔P0→P1〕**

目的：保持模型学习结果不变，观察采样本身怎样影响真实表示和层级结构。

步骤：

1. 先训练/复现有竞争力的原骨干，保存由验证任务选出的checkpoint。小图保留完整邻域训练参照；所有图保留常规采样训练参照。不得专挑层级最差的模型制造现象。
2. 在G_obs上执行分块逐层完整推理，存每层输入和输出，必要时CPU memmap。完整推理必须覆盖该层所有可见邻居，不是把fanout=64称作完整。
3. 选择预先分层的诊断节点：开发阶段500–2000个，覆盖度数、深度、类别和局部分散程度；最终确认节点与开发节点不混用。全体任务指标仍在完整评估划分上计算。
4. 固定同层的完整输入，只抽当前层邻居，测局部偏移；随后用真正多层采样得到端到端结果，两种设置分开保存。
5. 扫描fanout=4/8/16/32/64/full，保留实际k、N和删减比例；插入模块时复用完全相同的样本。
6. 在独立pilot采样上估计投影标准差σ，以预先设定的允许标准误δ确定确认阶段R，近似R≈(1.96σ/δ)²。确认阶段固定R；达到算力上限仍不精确时报告不确定性，不能将其解释为零偏差。
7. 可从128次pilot开始，确认阶段按512、2048、8192、必要时更高档位选择。采用流式均值、二阶矩和独立半样本均值，避免存储全部向量；保留可重建的采样种子。
8. 用开发阶段锁定的公式或方向，在独立节点/重复上检验预测。方向的选择与显著性检验不使用同一份噪声。

每个节点输出偏移、方差、MSE、层级相关字段、clamp率和回退率；每组输出均值、分位数、置信区间和数量。全图平均可能抵消相反方向，因此同时展示预定义分组，但不按“效果最好”临时分组。

**12．E3：多层传播与层级坍缩的联系〔P1〕**

层数2/3用于现实采样模型；层数4/8用于规模可控的D0/D1/D2，采用逐层显式采样/完整处理，避免递归邻居爆炸。深层设置的执行语义与标准多跳mini-batch分开标注。

对每层记录：完整基准、仅本层采样、从前层传播而来的随机输入、加入修正后的结果。比较“所有层修正”“仅首层”“仅末层”“逐层局部oracle修正”。最后一种仅用于定位作用环节，不能作为部署结果。

观察祖先顺序错误、分支间隔和任务信息何时丢失；核对残差和归一化是否放大或消除前一层效果。可用局部Jacobian向量乘积诊断误差传播方向，但不构建全图巨大Jacobian。

零均值匹配噪声构造在各自完整输出p的切空间中，匹配实际误差的协方差/主要特征值，再Exp_p回空间。用随机符号翻转的残差或高斯拟合作两种对照；保持样本数与计算位置相同，报告分布假设。

另外保留无采样的深层基线，用来区分普通oversmoothing/oversquashing与采样新增的损伤。修正后指标改善不能自动证明所有退化都由偏差造成。

**13．E4：针对机制的干预〔P1〕**

使用固定checkpoint和同一批样本，比较：

| 干预 | 做法 | 检查的解释 |
|---|---|---|
| 正常修正 | 正确系数与本节点方向 | 完整方法 |
| 反向修正 | step取负 | 方向是否有作用 |
| 打乱方向 | 在度数/深度/分散程度匹配组内交换方向 | 是否依赖局部信息 |
| 随机等范数方向 | 保留步长，随机切向方向 | 是否只是添加同尺度扰动 |
| 纯径向版本 | 投影到语义根的径向方向 | 分支改善是否需要横向分量 |
| 纯横向版本 | 去掉径向分量 | 深度与分支效应能否区分 |
| 仅幅度/仅方向 | 固定另一部分到验证集选值 | 动态系数与方向分别贡献多少 |

这些干预用于加强因果机制证据；它们仍受构造和模型条件限制，不能表述成所有真实网络的普遍因果定理。盲目反向修正未必处处恶化，保留例外并分析。

**14．E5：核心端到端训练〔P1〕**

主比较：两个主骨干 × 三个核心数据 × 原聚合/解析模块/简单缩放/jackknife × 两个训练fanout × 五个训练种子。数据或适配器尚未通过准备验收时，不把该单元标记为已完成；记录待解决依赖。

每个run执行：加载锁定数据与配置 → 保存初始化/种子 → 训练并记录验证曲线 → 按预定指标选checkpoint → 对固定推理预算网格评估 → 输出完整结果和失败字段。每个epoch/评估点记录训练损失、主任务指标、必要结构指标、时间、峰值内存和异常率。

区分下列模式：

| 训练 | 推理 | 解释 |
|---|---|---|
| 原模型 | 原模型 | 基准 |
| 原模型 | 加模块 | 无重训练的直接插入效果 |
| 加模块 | 加模块 | 与模块共同适应后的效果 |
| 加模块 | 关模块 | 依赖性诊断，有分布改变，不当作公平主基线 |

推理直接插入通常不新增训练run；利用原模型checkpoint完成。无需通过再训练才能修复的主张，需要这一模式单独支持。

所有模型初始任务损失相同。若最终方法引入层级正则或额外监督，必须增加“原骨干＋相同正则/监督”对照；不能把监督增益归给切空间修正。

对损失爆炸、NaN、OOM、长时间无进展记录失败原因；几何失败不得删除后只平均成功种子。每个方法报告成功率及失败配置。OOM若只因batch过大，可按统一规则重试，保留第一次失败记录。

**15．E6：训练/推理采样预算变化〔P1〕**

核心训练预算8和16对应两组独立checkpoint。每个checkpoint在4、8、16、32、64、full推理，形成训练预算×推理预算矩阵。补“同预算”“更紧预算”“更松预算”三个汇总口径。

无需为每个推理预算重新训练；不得在测试时针对每个格子再选系数。解析系数使用实际N、k自动计算；学习的门控或阻尼只用训练/验证信息确定。

结构目标是真实层级信息和预测稳定性，不要求完整邻域永远最优。采样训练可能具有正则化作用，前向误差减小与泛化改善要分别验证。[2026年采样训练分析](https://arxiv.org/html/2605.22480v1)

输出每个预算的性能、几何误差、实际消息数、耗时和置信区间；给质量—时间Pareto图。若对预算区间求面积，预先定义横轴为实际时间或消息数，并说明插值方式。

**16．E7：骨干、注意力与采样器兼容性〔P1/P2〕**

先完成L-Mean与L-Attn。L-Attn分为：固定消息和固定权重、固定消息但重算正常权重、整个前层都随机采样。逐步增加因素，避免把几种误差混成一个机制。

跨家族用HGCN类切空间聚合：保留其原始基点和更新，针对真实算子重新推导或构造适配。相同模块接口不保证相同系数通用。没有合理适配时保留原版作为边界对照，不能把失败模型悄悄删掉，也不能假称兼容已经建立。

采样器扩展顺序为：均匀无放回 → 均匀有放回 → 明确包含概率的重要性采样 → 标准子图sampler。固定fanout公式只能直接用于它的目标协议。重要性采样区分包含概率和每次抽取概率，带权修正/归一化都需要说明。重复抽到同一消息时不能去重后仍使用原k的系数。

可学习曲率作为独立扩展：先逐层固定曲率扫描，再使用相同曲率学习方案比较原模型与修正模型，记录曲率轨迹。把“只冻结曲率”作为消融，以检查增益是否来自改变有效尺度。

近期Lorentz层组件对照在一个主骨干、两个核心数据中进行；不额外引入预训练或改变任务头。至少保留一种合理强配置，不只与最简单骨干比较。[ILNN基础层](https://arxiv.org/html/2602.23981v1)

**17．E8：轻量性、等成本和双卡性能〔P1/P2〕**

模块微基准：固定d=64/128/256、k=4/8/16/32/64、目标节点batch=256/1024；包含对Log、矩计算、系数和Exp的分项计时。原聚合和修正聚合共享输入与实现优化；不能让原版使用低效Python循环而新版使用融合CUDA。

计时流程：先预热至少50步，再测量至少200步，执行3轮；GPU计时用CUDA events或同步边界，CPU采样用墙钟。报告p50/p95和离散程度。三轮使用相同输入轨迹；GPU型号、精度、功耗/时钟状态与其他任务占用写入日志。

端到端基准单独测训练和推理，覆盖正常度数及长尾batch。两张卡可同时做一般训练，但正式时间比较时另一张卡的任务应避免争用CPU/内存/磁盘；主结果可采用单任务独占测量，双卡总吞吐另报。

等时间预算B4：在验证数据上只根据耗时匹配更大fanout或多次采样聚合，目标时间差建议控制在±5%；无法匹配时报告真实差异和Pareto曲线。测试效果不参与匹配。多次采样合并时明确是合并消息后聚合还是合并预测，它们是不同算法。

轻量性的规划目标可设为端到端时间和显存额外开销尽量不超过约10%，它是设计目标，不是完成标准或已测事实。若超过，需要如实展示质量—成本收益；不能删去采样、数据搬运或统计计算时间。

双卡调度默认GPU0/GPU1各跑一个run；任务启动前检查目标卡空闲，避免两个任务意外落到GPU0。DDP仅作为可选工程比较，用同一有效batch与训练样本数计公平效率。

**18．E9：消融、失败区间和稳健性〔P1/P2〕**

最小消融集合：去掉动态采样系数、去掉局部不对称性、仅径向、仅一层、固定阻尼/无阻尼、stop-gradient、固定/可学曲率、强归一化前后位置。不是每项都铺满所有数据；预先选一个稀疏taxonomy和一个高连接真实图，按结构特征选择，不按方法收益选择。

失败与稳健性集合：

- k=1/2、N≤k、孤立节点、低度占多数：回退率与收益覆盖率。
- 大局部分散、离群邻居、极高注意力集中：矩估计方差及步长稳定性。
- 对称邻域、弱层级图：模块是否无端破坏正确表示。
- 层级与度数关联弱/相反：系数是否只是学习度数捷径。
- 标签噪声、多父、多路径：单径向假设的限制。
- FP32/FP64、不同clamp、BF16欧氏层：几何与数值效应区分。
- 骨干已用强残差/归一化/近期组件：是否仍有新增价值。
- 输入变成更强的统一文本特征：收益是否被更强输入完全替代。

若只有“偏差下降、MSE上升”，单列；若只有结构指标改善而任务不改善，讨论结构—任务对齐；若原完整模型本来就不编码层级，不把低采样结果称作“丢失原有层级”。[Geometry–Task Alignment](https://arxiv.org/html/2602.01828v2)

**19．训练运行矩阵：区分新训练与复用评估**

一个“训练run”指一次独立初始化并训练到既定停止条件。一个checkpoint的六个推理预算、逐层分析和推理插入模块，不计为六次新训练。共用原基线checkpoint的结果不得重复计算训练成本。

下面D1/D2的训练数量指协议B；完整邻域训练参照也只使用G_obs。协议A如果额外专门训练表示模型，应在manifest新增run及成本，不能直接把协议B在删边图上的结果当作协议A结果。D0的专门训练和额外确认实验也需另计。

| 组别 | 计算方式 | 正式训练run数 | 说明 |

| 无图MLP | 3数据×5种子 | 15 | 没有邻居采样预算 |
| 完整邻域训练参照 | 2小taxonomy×2骨干×5种子 | 20 | 能完整训练时执行 |
| **核心合计** |  | **305** | 先开发，正式确认补齐五种子 |

四个主要方法的完整网格承担公平性；大量消融只在两个预先选定场景进行。若研究最终不提出某项兼容性主张，可相应删去整组并记录原因。保留主张时应保留证据组。

**20．超参数搜索、训练停止与模型选择**

先进行较短的验证集搜索，再冻结正式配置。共同参数包括维度、层数、学习率、衰减、dropout、任务头；方法特有参数包括缩放幅度、jackknife阻尼、修正步长控制。解析原版没有新增可学参数，也仍需共享骨干调参。

建立HPO manifest，记录每个方法的搜索空间、试验次数、最大训练数据量/时间、失败次数。方法间分配相同验证预算；完整模型可再给一组共同超参数的严格配对结果。新方法不享有额外测试反馈。

启动停止规则建议：

- D1/D2：最多400 epochs，每5 epochs验证一次；至少40 epochs后，连续20个验证点无主指标改善则早停。
- D3/D4/D5：最多100 epochs，每epoch验证；至少10 epochs后，连续10个验证点无主指标改善则早停。
- epoch含义固定为一遍训练目标节点或训练关系对；批大小变化时同时记录优化步数和样本曝光量。
- 主验证指标按任务固定；多个指标不临时加权。并列时优先更早checkpoint。
- 训练数值失败触发统一恢复规则；学习率回退或新clamp属于新配置，不能在原run里悄悄修改。

上述规则根据P0运行时间可整体调整一次，所有方法同步，并在正式测试前冻结。短调参run不进入五种子结果；短调参与正式训练总成本分别列出。后文80个短run只用于时间敏感性示例，真实HPO总量以manifest为准。

**21．统计分析与结果可信度**

首要统计单位是独立训练种子；合成图还包括独立图生成种子。不能把数百万节点、R次采样或多次评估当作数百万次独立训练。

正式主表报告五种子的均值与标准差，另报告同种子配对差值和置信区间。样本少时同时展示每个种子的原始值，避免只给一个精确p值。若使用t区间说明样本量与假设；bootstrap以种子为外层，不把节点当作唯一重采样单位。

节点/关系级结构结果可做按子树、类别或实体组的聚类bootstrap，并报告聚类规则；MeSH多路径造成组重叠时，实体是至少需要合并的单位。图依赖性使简单iid区间不充分，应把这种区间定位为条件于当前图的描述，而非无限图总体保证。

预先注册每个任务的一个主任务指标及一到两个主结构指标；其余为探索分析。同一确认性比较家族使用预定的多重比较处理，例如Holm校正；原始效应量和置信区间仍全部展示。

几何零均值检验应避免只检验||barξ||>0；见07.1。通过pilot决定R后用独立确认采样，避免反复采样到“显著”为止。理论预测方向、分组边界和失效阈值在确认集打开前固定。

缺失与失败报告：表中注明失败种子数、OOM重试、几何无效值、数据覆盖率；不能用0填充未知结果，也不能忽略失败后只报成功均值。大图若只有三种子，明确标记，并对效应很小的结论降低确定性。

**22．GPU小时、双卡排期与预算更新**

当前没有在目标机实测，不能从显卡理论TFLOPS推出训练耗时。图采样、CPU内存、PCIe和Log/Exp可能决定实际吞吐。

迁移后选三个代表配置做计时：D1的小图、D3的中大图、D5的大图；每个都测原版和模块版，分别记录采样/传输/前向/反向/验证。一次成功的训练计时后再修订总体预算，初始微基准不能代替完整epoch。

预算公式：

$$H_{GPU}=\sum_j n_j\,\tau_j\,g_j+H_{HPO}+H_{diagnostic}+H_{features},$$

其中n_j是run数量，τ_j是单run墙钟小时，g_j是使用GPU数量。双卡DDP一小时计两GPU小时；两张卡各跑一小时也合计两GPU小时。

理想化日历下界/计划值可按：

$$T_{days}\approx H_{GPU}/(2\times24\times u),$$

u表示任务之间空闲、评估、失败重跑及调度损耗后的有效利用率，不等于nvidia-smi中的瞬时GPU利用率。对CPU准备、人工排查、串行依赖另计时间。

下表只说明完整455-run方案对单次训练耗时有多敏感，**不是L40S性能预测，也不是交付承诺**：

| 假设情景 | 正式run平均GPU小时 | 80个短run的平均GPU小时 | 诊断/特征等额外GPU小时 | 合计GPU小时 | 两卡、u=0.75时约天数 |
|---|---:|---:|---:|---:|---:|
| 单次较快 | 0.5 | 0.125 | 40 | 277.5 | 7.7 |
| 单次中等 | 1.5 | 0.25 | 80 | 782.5 | 21.7 |
| 单次较慢 | 4 | 0.5 | 160 | 2020 | 56.1 |

优先通过复用checkpoint、分层诊断、统一特征缓存和两卡独立调度节约时间。首先保证核心305-run及必要机制证据；扩展组按其支持的论文主张排期，不通过删掉不利结果节约成本。

**25．每个run必须留下的记录**

| 文件/记录 | 必需内容 |
|---|---|
| config.yaml | 最终解析后的全部配置；不只保存差异项 |

| train_metrics.jsonl | step/epoch、损失、验证指标、时间、内存、异常率 |
| checkpoint | 模型、优化器、随机数、采样器和选中理由 |
| eval_metrics.jsonl | 任务、预算、种子、指标值、样本/候选数与统计口径 |
| sampling_stats.json | 每层N/k、覆盖率、重复情况、关系与方向 |
| geometry_stats.json | 偏移、MSE、方差、理论残差、clamp/回退率 |
| status.json | planned/running/completed/failed，失败原因与重试关系 |
| runtime.json | 精度、预热、计时步数、设备状态、纯计算与端到端时间 |

全局manifest字段至少包含run_id、研究阶段、数据版本、协议、模型、方法、训练/推理预算、seed、code_hash、config_hash、data_hash、状态、GPU小时、结果路径。训练run与其多个评估任务分开记录；结果表由manifest生成，禁止手工把最优数字复制进主表。

采样重复的原始向量不必全部长期保存；保存流式充分统计、抽样计划、少量可视化样本和重建代码即可。完整邻域每层缓存可存CPU memmap，并记录精度；不让缓存随着run无限复制。

**27．容易被审稿人追问的问题，实验中如何提前回答**

| 问题 | 预先准备的回答证据 |
|---|---|
| 只是采样噪声吗？ | 固定切空间的平均偏移、独立确认、协方差匹配零均值对照 |
| 只是普通深层GNN退化吗？ | 无采样深层、仅本层采样和逐层传播分离 |
| 半径变小就叫坍缩吗？ | 真实祖先/分支指标和尺度不敏感排序 |
| 只是在恢复一个本来不好的完整聚合吗？ | 真实任务、完整参照与采样训练泛化分别报告 |
| 简单缩放或jackknife是否同样有效？ | B2/B3及同时间预算比较 |
| 为什么不多采几个邻居？ | 实测Pareto和成本匹配B4 |
| 修正器用了完整邻域或测试层级吗？ | 接口限制、oracle标记、可见图与评估器分离 |
| 是否只是数值稳定性收益？ | FP64子集、clamp计数、近期层组件对照 |
| 为什么选这些数据和节点？ | 预先列出的数据职责、覆盖率、固定分组、全部结果 |
| 能泛化到其他骨干吗？ | 不同聚合接口、独立适配条件和未支持场景 |
| 调参或失败种子是否不公平？ | HPO清单、配对seed、失败率及未筛选原始记录 |
