# 按阶段推进的执行计划

2026-09-16：用户明确授权按“E0收尾 → E1机制实验及真实基准准备 → E2/E3冻结诊断 → E4/E5干预与训练比较”的顺序推进。本文更新此前仅初步 smoke 的执行范围，保留所有资源隔离与证据边界。

## 分工与共同规则

- 代码任务拥有 src、tests、scripts、configs 和安装配置。每阶段实现与测试通过后发布可复现 commit，再继续下一阶段；不要等待整套实验代码全部写完才交付。
- 实验任务拥有远程部署、Slurm作业和实际运行证据；只能运行明确的已提交代码快照，不能在代码任务编辑中的工作区打包。使用 git archive 对固定 commit 导出，或在服务器隔离的 release 目录检出相同 commit。日志记录真实源版本。
- 父任务负责研究协议、指标解释、实验验收和整体汇报。对子任务的复核是内部质量流程，不等于反复向用户要许可。
- 单个 smoke / 回归作业最多1张L40、30分钟；E1优先CPU调度或小批量单卡。后续真实基准先用1张L40，以10–20步测量和1个有时间上限的开发run定标，首轮单作业至多1小时。达到上限保存状态、评估瓶颈和更新预算，不能无限重试或重复提交。
- 数据下载、CPU解析、特征预处理与GPU训练分开；保护CVPR两张卡。组内八卡额度不是本项目全部占用的配额。增加并行度依据阶段任务与可用资源，不能改变其他项目分配。
- 每阶段写机器可读结果、对应公开报告和简短状态；私有连接、调度原始输出、JobID保存在.local。历史报告不可改写成新版本证据。科学负结果必须保留。

## S0：E0加固版本回归

起始待回归源码是 `9e610cbc16acfeff0d0790c63a0a11d28c4b9cb6`，本地78项测试通过。先检查依赖并运行远程CPU测试，再在单张L40上运行真实CUDA批量/参考路径检查：FP32输出与梯度、混合N/k、完整采样与低k回退、重合/近重合点，以及8步小图smoke。不要只在GPU分配里跑CPU测试就称CUDA回归通过。

输出 `reports/E0_REMOTE_REGRESSION.md` 与带commit/设备/退出状态/测试范围的JSON。计时分为作业占用、测试、模型步骤；显存说明是PyTorch allocated/reserved还是完整进程占用。

此项通过即可开始该版本上的机制检查；新E1代码若修改几何核心须有相应回归。代码已经稳定的检查不无故重复。

## S1a：E1受控机制

目标是验证可预测的几何偏移、适用条件和偏差—方差交换，不预设方法在每个条件上获胜。

首轮固定N=16、d=2、c=1，以对称、非对称及反向非对称邻域扫描k=1/2/3/4/8/16和若干预先固定的局部离散尺度。保留二维构型，不全用单测地线。实现分块批量计算，枚举与Monte Carlo的选择依据组合数阈值，不能依据结果选择。

- 比较完整参照、原采样聚合、候选三阶矩修正、几何jackknife。简单缩放须有明确、冻结的操作定义；未实现时报告缺口，不冒用不同算法名称。
- 小组合数使用精确枚举；较大组合数固定采样种子、重复数和分块大小，方法之间复用同一采样轨迹。报告枚举/MC、重复数、随机误差及可能的有限MC偏差，不能把样本平均向量范数直接当作精确总体偏差。
- 明确计算 E[Log_p(Y)]、误差二阶矩、方差、半径变化、方向预测、回退与裁剪。p是同一固定输入的完整聚合输出；不同样本的切向量必须在同一基点比较。
- 与候选局部公式对照；不要把部署时0.1步长裁剪后的结果直接称为未裁剪解析式的验证。分别标明解析诊断与受保护实现，记录所有触发与越域条件。
- 当前代码限制坐标原点缩放半径<=3；这不是局部邻域假设。等距变换对照限于实际支持范围；越域要显式报告，不静默重采样或放松约束去求正结果。

首轮输出配置/结果JSON及至少三类图：偏移方向与采样量；偏差、方差、MSE的对照；局部尺度与预测误差。生成静态可导出图，所有图能从同一结果文件重建。

随后依据首轮实现和耗时，补曲率/维度及匹配零均值噪声等定向条件，不做全笛卡尔积。图级D0控制层级真值与传播图的区别，人工坐标分析与弱特征训练分开。

## S1b：真实数据与原骨干准备

在E1实施同时进行数据协议准备；不能把准备工作误记为已完成真实训练。

1. 保存WordNet/MeSH原图和候选G_obs的节点/边/方向/度数审计。对fanout=4/8/16/32/64报告 P(N>f)、实际k/N、消息删减比例，并同时报告全体及实际删减节点。父任务可先做原图审计，正式划分后的G_obs仍需独立审计。
2. 依据详细路线05.3区分协议A（已知结构表示保真）和B（未知关系恢复）。旧 `split_relations` 是小图保守测试helper，不直接作为正式划分；它对所有可达关系隔离，与正式按子节点分组80/10/10的设计不是同一个协议。
3. 协议B按子节点分组，父边及副本保持同一划分；消息图只含训练边及规定的反向边。不得利用测试边生成闭包再加入输入。训练图自然存在的多跳路径本身不一概判为泄漏；若另做可达关系筛除，应作为独立协议说明。
4. MeSH保留descriptor的所有合法tree位置/祖先集合，tree编码不作特征；多父/多位置不能硬套唯一深度。现有歧义隔离记录继续保留。WordNet名词@/@i口径固定。
5. 输入先使用详细路线规定的名称/定义文本TF-IDF+SVD，词表/IDF/SVD只在允许的训练实体文本上拟合。保存实体划分、文本字段、特征版本与哈希；不以标签路径生成输入特征。文本与结构schema不足时先补解析。
6. 先实现并验证一个明确的两层原始Lorentz-Mean骨干与统一任务头；TinyGNN是工程示例，不能直接宣称已复现有竞争力的正式基线。完整与采样的同参数输出要可比较；数值域参数化不能随隐藏维度无意改变表示范围。
7. 先做1个数据/1个骨干的有界开发训练，保存验证选择checkpoint。正式多种子前锁定任务和选择规则；不得挑层级最差checkpoint制造现象。

输出任务协议、可重建划分与特征清单、原骨干checkpoint和实测性能/成本。若taxonomy实际采样覆盖率很低，应保留边界结论并按既定路线考虑自然更高连接的数据，不偷偷增边制造层级坍缩。

## S2：E2/E3冻结诊断

基于S1有效checkpoint，固定权重和输入，在G_obs上缓存逐层完整输出。开发节点预先按度数、深度及分支分层，起步500–2000节点；完整任务指标仍在完整评估划分计算。

分别测“单层输入固定、仅当前层采样”与“真实多层采样传播”。同一checkpoint复用多个推理fanout，方法复用采样轨迹。用独立pilot估计重复数，确认阶段冻结设置；流式累积统计，避免存储全部大张量。

证据链是：有方向的偏移 → 具体祖先/深度/分支关系损失 → 与匹配零均值噪声或无采样传播的差异。单纯半径变窄/变大不构成层级坍缩，低统计精度也不等于零效应。反方向或相互抵消的效应按预定义分组报告。

输出结构/几何/任务指标、置信区间、传播轨迹和失败条件。根据观察修订机制解释，保留负结果。

## S3：E4/E5干预与训练比较

在已有冻结checkpoint与同一批样本上比较正常修正、反向、打乱/等范数随机方向等机制干预，先区分方向信息与单纯扰动。模块形式在开发集确定，测试集不用于选系数或更换数据。

随后按明确主张安排原模型、候选模块与关键对照的有界端到端开发比较。分别标明原模型推理插入、带模块训练、关模块诊断，复用可复用checkpoint。达到可信的开发证据后，再登记正式多种子与扩展矩阵；不得将历史455次规划当成启动指令。

阶段推进条件是实现正确、协议有效、统计结果可解释和成本有记录，不是“结果必须显著提升”。遇到科学假设不符时先分析和汇报，不能连续扩大数据/参数搜索去追逐题目。

## 本轮监督方式

父任务在本对话维护整体进展与解释；每30分钟检查两个子任务，有变化才汇报。源代码任务和运行任务通过明确commit交接。E0/E1完成不终止用户已授权的后续流程；完成S3开发验收后总结已建立与未建立的结论，并停止无计划追加计算。
