# E2 骨干排查下一步：固定权重诊断方案 v1

研究问题：在当前两个已训练骨干中，批次遮蔽与邻居采样分别怎样改变评分和梯度；第二层径向集中是否同时表现为局部压缩和实际梯度变化？目的是决定下一次训练应优先改变哪个因素，不在本步证明某个新架构有效。

状态：**方案与本机离线工程已验收；真实数据前向/反向尚未执行，等待用户批准这一关键诊断。** 工程范围与限制见 [主管复核](../../reports/E2_BACKBONE_FROZEN_SUPERVISOR_REVIEW.md)。不更新权重，不新增训练，不进入 E3。依据是用户要求关键实验先完成质量和预定指标验收并取得本人同意。主管不能代替用户放行。

## 为什么先做这一步

已有排名分解表明，目标父节点 degree>16 的 2900/8456 条查询贡献了两个 seed 的全部净 MLP 优势，其他组净效应部分抵消；不能据此认定度数或采样是原因。非空邻域没有显式自身消息通道，以及第二层径向集中，是明确的实现事实，但其性能作用仍待识别。只把推理改成 f16 的旧记录没有追回整体差距。

已有full第二层输出坐标的补查还显示：该高degree parent组的origin输出near-bound比例29.52%/28.90%，并非各组最高；因此不能把净差距直接等同于该组更严重的输出饱和。旧证据没有逐节点message半径，本步观察Linear输出及其局部压缩正是补齐这一读数，不能混用message与聚合output。

先用同一权重改变计算条件，可以在不重新训练的情况下检查机制读数是否值得追踪。无效或混合结果也是有效交付；不以获得正结果为停止条件。

## 固定对象与计算矩阵

- 原 GNN 训练源 `b6269f24e33602c10c39ee6b9bac57fe0901a405`；两 seed 均使用原 full-valid 选出的 step768 best。seed11 文件 SHA256 为 `b3afb5f84fda3d893da21548e7f51165f029880fd4d3e9e85fcb544b344dac4d`，seed23 为 `a28c65150297250a18b29cd3e1fc729c2fb3f2437cf1290dcf4105f943af00b1`。
- 保持原128维特征、图、关系头、c=1、半径参数1.2和 FP32。prepared 身份须与 [数据诊断](../../reports/e2-backbone-data-diagnosis.json) 及原 run 一致；PyTorch 使用原2.5.1环境。
- 每 seed 仅重建原训练抽批流中的第769、770批，每批128个正例组及原每正4负，共640个评分。选定它们因为紧接 best 保存步，不能看读数后更换批次。逐批索引须与已有 MLP 的同种子历史批次 hash 对上。
- 对同一权重、同一批查询，比较 `原 Gobs / 去掉本批全部正边及反向` × `完整邻域 / 两层 f16`。full 各1次，f16 各8次；每 seed 2批×(2+2×8)=36次，共72次前向/反向。工程等价校验的额外前向单独计数。
- 采样保持原规则：每层均匀无放回，N≤16全取，两个层顺序消耗同一专用 CPU generator。每个 `(seed, batch_step, replicate)` 的种子由字符串 `E2-BACKBONE-FROZEN-v1|seed|batch_step|replicate` 的 UTF-8 SHA256 前8字节大端、再对 `2**63` 取模确定，replicate=0…7。两种图条件重置为同一初始种子，但候选集合和随机流消耗可能不同，**不声称抽到相同边或完美共同随机数配对**。不得改用确认入口的独立层随机流。
- 只用 train 批次标签；使用独立train-only loader，核对manifest/原run/检查点保存的身份，不调用会额外读取valid标签的旧loader。不访问 test/truth，不做新完整 valid 排名或选模。原完整 valid 的事后 degree 分解另行保留。

## 必须输出的读数

1. **输入和表示路径**：每条件两层 N/k、消息数、空邻域比例；正例 parent/child 的 degree0、1、2–16、>16（以未mask的 Gobs 度数固定分组），并另记 mask 后度数及非空→空切换。保留组大小和唯一节点数，不能混合不同分母。
2. **同权重评分变化**：640条 query 的原始 logit、逐条 BCE，及128组的正例 logit 减四负平均 logit。完整保留配对差，按固定正例 parent 度数分组汇总；五条监督记录按其所属正例组归组，不能把负例 parent 当该组的真实 parent。另报告 child 分组，不把两套分组贡献相加。
3. **局部径向压缩**：逐层记录 Linear 输出 `u` 的范数 s、参数化半径 `R*s/sqrt(1+s²)`、near-bound≥0.95R比例，以及解析 Jacobian 径向/横向系数 `R/sqrt(c)/(1+s²)^(3/2)` 和 `R/sqrt(c)/sqrt(1+s²)`。按全体唯一节点、正例 parent/child 出现次数分别汇总分位数，记录零范数情况。这是 exp 之前的局部导数，不是整网梯度。
4. **实际梯度**：对原640条监督的平均 BCE 做一次 backward，不调用 optimizer。记录各参数梯度范数、有限值、精确零元素比例；保存两层 `dL/du` 的节点范数与沿 u 的径向/垂直分量摘要。s=0 的方向分解单列 undefined 数，不能伪造方向。平均损失的缩放固定，不以梯度小或大直接判定训练成功/失败。
5. **配对比较**：遮蔽在 full 下的差、f16相对full在两种图下的差，以及两者交互差。8次采样只报全部重复、均值/标准差/范围及方向计数，不进行确认性p值检验，不据此选“最好一次”。原始节点级/查询级读数保留私有，公开仅必要汇总、索引流和文件hash。

**解释边界**：unmasked 训练查询的目标边位于图中，因此其评分有目标信息可见的影响；它只用于计算路径敏感性，不能作为验证成绩，不能由此建议训练时取消目标遮蔽。固定权重干预也不等于重新训练后的泛化效果。此步不直接测量自身文本的最终信息保留，不给“无self导致全部差距”下结论。

梯度的径向/垂直分解相对于Linear输出u的欧氏方向；它不是E2相对于H_dev参考根的径向偏移，也不是Riemannian参数梯度。原点参数化半径、参考根距离、语义层级深度必须继续分开。

## 工程与验收门槛

真实执行前，代码任务交付独立入口、固定配置及有意义的小图 CPU 测试，主管复核后仍需用户同意。原训练模块和历史结果不改写；观测通过 hooks 或独立旁路完成，不能给旧 checkpoint 加 self、激活或新参数。

- 核对固定训练相关源码的LF语义hash、prepared清单、节点顺序、图、训练query及 checkpoint SHA；strict load，无 missing/unexpected key。
- 原模型未加观测与加观测的同图/计划输出、640条 logit 应满足 `atol=2e-6, rtol=2e-5`；同损失参数梯度也在该容差内。真实运行只在每seed第769批的四个图/采样条件做此前置校验（f16固定rep0），共额外8次plain前向/反向，对照相应科学实现并单列成本；不把整个72次矩阵再重复一遍。先用小图 FP64 做更严格等价及导数测试。若真实硬件不满足，保留失败并调查，不放松门槛后称原协议通过。
- 输入、计划及顺序确定；N≤16无采样删除、遮蔽双向、空行自身回退均有小图检查。原历史batch hash不匹配即停止，不能换新流替代。
- 所有损失/读数/应有梯度有限；精确零梯度比例和径向集中是观察量，不能设成必须改善的质量门槛。只要求预定义字段、组数、72次矩阵完整，缺组用0计数/null而非删除。
- 每次 backward 清空旧梯度；每条件前后、全作业前后权重和输入hash完全相同。代码入口不创建 optimizer，不保存新 best/last，不改变学习率或参数。
- 对无数据、错误来源、不匹配权重、非有限值、超时、部分结果明确非零退出，保留失败证据。tiny fixture不下载真实数据。

## 后续训练如何选择

本步是探索诊断，不把读数阈值伪装成理论验收线。若不同批次/种子方向一致，可将对应因素列为优先训练对照；若混合，则完整报告混合，并选最直接、可解释的单因素设计，而非追加诊断直到一致。

下一次训练另行提出同初始化、同监督/批次/预算/选模机会的最小比较。候选是给原聚合加入**明确自身消息权重**（并写清随度数的权重定义），或隔离第二层径向参数化；不能一次同时改self、半径、激活和学习率。欧氏图模型用于随后分清“图聚合本身”与“双曲参数化”，不是用MLP差距直接归因曲率。任何正式新版本仍需独立质量验收及用户同意。即使新骨干超过当前MLP，也只满足这个有界参照，不能宣布达到SOTA。
