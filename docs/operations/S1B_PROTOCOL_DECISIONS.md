# S1b 协议审查与冻结决定 V1

日期：2026-09-16。父监督任务依据用户已授权的分阶段执行顺序审查 `reports/S1B_PROTOCOL_DRAFT.md`。以下是第一版开发协议的冻结决定，不是已完成真实数据训练的声明。代码通过相应验收后，实验任务可直接开展预处理、短步测速与有界基准训练，无需再次请求用户确认。

## 1. 实体分组与可见信息

接受对**全部稳定实体ID**（含根、孤立实体）做80/10/10分组，为文本拟合集合提供一致定义。排序、去重后使用固定置换；**数据划分种子使用详细实验路线原定的20260914**，不复用训练种子11。训练种子可以是11/23/37等，必须与数据划分种子分开记录。

每条直接父关系按子实体分组，同一子实体的全部父关系处于同一集合。根/孤立实体没有相应正查询，但仍属于实体划分；明确报告各集合的实体数、有监督查询的实体数、正关系数、根/孤立数。因此不是保证每组关系边恰好80/10/10。

模型设置为transductive：所有实体ID及可用文本已知；训练图仅由训练父关系及其反向组成。held-out子实体可作为其他训练子实体的父节点出现，这不补回其held-out父关系。不得声称从未见实体归纳泛化。

协议A（已知结构表示保真）仍单独标识；首轮真实基准采用协议B。保持自然多跳路径，不采用旧helper的可达关系全面隔离。

## 2. 文本与MeSH

接受草稿的WordNet词名+gloss、MeSH名称+preferred concept ScopeNote；tree编码、祖先列表和完整图深度不能进入输入特征。TF-IDF、IDF和SVD仅在实体train组拟合，其余只transform；保存拟合实体清单、模型参数和内容哈希，缺文本与不足秩条件显式记录。

MeSH以descriptor为实体，保留所有路径和祖先集合。官方歧义位置继续隔离、记录缺失范围；路径元数据仅进入评估，不丢掉多位置实体来制造唯一层级。正式G_obs需要独立度数/采样覆盖率审计。

## 3. 训练目标和查询屏蔽

接受每个训练正父关系配4个固定均匀负父候选；排除self和这个训练子实体的已知全部真父，单组负例不重复。该过滤只读train关系。所有方法共享负例、初始状态和采样计划。

每个优化batch的全部正查询边及反向边，必须在两层采样计划生成前统一屏蔽；N按屏蔽后的候选集合计算。不得只屏蔽最终输出层或仅在打分函数中忽略目标边。全邻域训练也需同样屏蔽。

BCEWithLogits作为第一版统一训练目标；记录实际正负比例。未经登记不得为修正方法单独增加监督或正则。

## 4. 模型定义与数值约束

接受自建两层Lorentz-Mean作为开发起步骨干，不称为某篇已发表模型的复现。每层映射、尺度界、曲率和统一有向关系MLP都需保存配置。宽度无关的径向约束可以作为明确的工程选择；记录每层半径与饱和情况，不能把参数化自身的压缩误归于采样。

完整与采样使用同一权重、消息变换和关系头。两层固定输入的局部采样诊断与真正两层传播分开保存。正式结果前仍需评估基线是否有合理任务能力；只比随机好不足以宣称有竞争力。

## 5. 验证与测试排名

主选择指标冻结为**完整验证查询集上的filtered all-candidate MRR**。候选是全部已知实体减self；每个目标父保留，只在评估器过滤该子的其他真父。同分平均秩：1+严格高分候选数+0.5×其他同分候选数。

主MRR对正关系查询取平均，另报告按子实体先平均再跨实体平均的版本，以展示多父实体权重的影响。Hits@1/3/10和候选规模同时报告。相同主指标并列选更早checkpoint；若差异仅在显示舍入位而底层不同，不按显示值判并列。

测试集不用于选epoch、超参数、数据方向或采样预算。开发表现监测可使用事先固定的验证查询子集，但必须标为`validation_probe`并记录ID和哈希，不能冒充完整验证集MRR，也不能以它替代正式checkpoint选择。1000抽样候选若实现须另命名，不能与全候选结果混用。

## 6. 先优化全候选评估，再开始计费训练

WordNet约8万实体，全验证全候选评分规模不可忽略。评分必须分块，不能创建完整查询×候选大张量；每次评估先缓存节点的Log_o向量，不应每个候选块重新对全图做Log/编码。

对于当前头 `Linear([p,c,p-c]) → ReLU → Linear`，第一层严格等价于 `(W_p+W_d)p + (W_c-W_d)c + b`。可预计算父候选投影和子查询投影，分块相加后执行ReLU和最后一层。此优化必须与直接MLP对照值/梯度或评价分数，不改变候选、过滤或平均同分规则。

全图每优化步重编码/逐节点Python采样的成本也须短步测量。训练单步、验证一次、保存checkpoint分别计时，再确定开发运行的验证频率。不要因为验证慢而静默改用抽样排名。

## 7. 首轮执行门槛与范围

- 协议fixture通过：分组/多父、文本fit隔离、正查询屏蔽、多位置元数据、全邻域一致和排名/过滤/同分。
- 在固定commit上完成真实预处理、哈希和G_obs审计；预处理CPU运行，下载不占GPU。
- 先选择WordNet协议B、一个原Lorentz-Mean配置和一个训练种子做开发测量，不是正式多种子结果。
- 单L40先10–20步测速并测一次有明确规模的验证评分，首个训练作业至多1小时；保存模型、优化器、随机状态与选择指标，不能仅因到时而丢结果或报告为训练收敛。
- 正式完整验证、checkpoint选择和冻结诊断需要真实训练runner接通，并在明确协议和时间预算内执行。配置重复、数值错误或统计精度不足时记录并修复，不以筛选正结果代替研究。

草稿可以根据这些决定更新为冻结V1；未来改变划分、主指标或模型定义必须留版本与理由，尤其不能在观察测试结果后追溯修改。
