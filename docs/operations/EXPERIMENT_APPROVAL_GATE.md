# 关键实验的质量、指标与用户批准门槛

生效日期：2026-09-16。用户原话：

> 每一个关键实验步骤必须在质量验收和关键指标通过，以及我的同意后才能继续

此规则覆盖此前笼统的按顺序自动推进和主管条件批准。主管负责审查、提出建议、组织材料；最终是否进入下一关键实验由用户决定。资源允许多卡，不代表任何实验已获批准。

## 三项条件缺一不可

1. **质量验收**：数据与标签边界、实现和必要测试、固定源码与结果来源、数值稳定性、运行完整性、可重复性及资源记录符合该实验约定。
2. **关键指标验收**：在执行前写清指标、计算口径、阈值或通过条件；按真实结果标为通过、不通过或证据不足。质量正确和科学假设成立分别报告，不把代码运行成功当研究结论，不因结果不理想而事后降低门槛。
3. **用户明确同意**：向用户提供本阶段结果、验收结论和下一步具体方案后，获得明确同意。记录对应用户消息、批准的阶段/子步骤、固定版本、配置、数据及资源边界。主管确认、代码就绪、空闲GPU、过去笼统授权、沉默或等待时间都不能替代这一项。

如果关键指标未通过或尚无预先约定阈值，不自动进入下一步。先解释不足及可审查的修复/补充提案，待用户决定；不能将补充实验排除在批准规则之外。

## 自动监督

自动监督只监测当前已批准范围、验收和整理提案，不自动开启下一关键实验。状态至少区分准备中、待质量验收、指标未通过/不足、待用户批准、已批准待运行、运行中、已完成。用户批准到达后才能更新可执行范围。
